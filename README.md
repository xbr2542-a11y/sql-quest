# 数据部新人 · 用游戏学 SQL

一个把 SQL 学习包装成「入职上班」的网页小游戏：接需求单、写真实 SQL、拿绩效评价和涨薪。
所有 SQL 在浏览器本地由真实 SQLite 引擎执行，不需要后端、不联网也能玩。

**在线体验**：https://xbr2542-a11y.github.io/sql-quest/
**源码仓库**：https://github.com/xbr2542-a11y/sql-quest

> 线上地址由 GitHub Pages 托管（推送即自动部署）。国内可访问，但 `*.github.io` 的稳定性看运营商；要稳定给国内用户用，请看 [DEPLOY.md](DEPLOY.md) 第九节。

## 玩法结构

- **入职第一课：亲手写出第一条 SQL（8 步）**：聚光灯高亮当前区域，遮罩挡住其他区域。编辑器**从空白开始**——不是给你模板照着填，而是逐步引导你自己写：先打第一个词 `SELECT`（并解释它回答「我要看什么」），再补 `FROM products`（回答「从哪张表拿」），然后执行看结果。每一步都会**真实验证你做没做到**：写错会当场指出（「第一个词应该是 SELECT，你现在写的是 FROM——想想它回答的是哪个问题？」），没做到就不会放你过下一步。
- **没有无条件放行**：指引里不再有「我做好了」这种能蒙过去的按钮。没完成时按钮是「点这里，我帮你做」——由程序真的把这一步做掉，然后自动进入下一步。
- **Ctrl + Enter 随处可用**：不管光标在编辑器、右栏还是工具条上，都能执行。
- **真实的 SQL 客户端界面**：左侧数据库对象树（可展开看字段、点字段名插入编辑器）、顶部连接状态与查询标签页、中间深色编辑区、下方「我的结果 / 参考答案 / 差异分析」标签页、底部状态栏（引擎、行数、耗时）。
- **两条线，一套内容**：基础线（1–12 关，从 `SELECT` 到 `JOIN`）与业务线（13–18 关，渠道看板、爆款、复购率、退款排查）。两边的关卡共用同一份数据与进度，只是入口不同。
- **需求单驱动**：每关先给一段两三行的业务场景，再给明确口径。没有对话系统，不浪费时间。
- **给零基础的大白话讲解**：每关右侧有「这关在教什么」，用日常语言解释这个知识点为什么存在；示例 SQL 会被逐词标注，`SELECT` 是「要从表里取出哪些列」，`WHERE` 是「只保留满足条件的行」。
- **剧情驱动**：每关都是一个人找你要东西——主管、运营、供应链、质量部。右侧先给一句旁白场景，再给一张带角色头像的对话气泡，明确「为什么要现在做」；过关后的绩效单上会告诉你「这件事的结果」（比如「老吴按你的清单备货，避开了给取消订单的滞销商品压库存」）。
- **结果集判定**：判定只看结果，不看写法。比对列数、行数、单元格值；列名默认不校验（别名自由），浮点带容差，排序敏感性按关卡单独配置。零行的错误结果不会再被误报成「没有结果」。
- **指着字段说话的报错**：不会只说「期望 3 列返回 2 列」，而是「你只返回了 1 列，这一关要求 6 列，少的是 `product_id`、`category`、`price`…」；别名写错会说「第 1 列要求叫 `product_name`，你写的是 `productname`（看着像是下划线的问题）」。判定之后还有一层「SQL 体检」，根据你的写法猜可能的原因：漏了 `WHERE`、忘了过滤订单状态、把空值写成 `= NULL`、漏了 `GROUP BY`、排序方向反了、用了中文标点……每次最多给 4 条。
- **表结构不用猜**：每关右侧直接列出用到的表和每个字段的中文含义，点字段名插进编辑器，点「看数据」在下方看真实样例数据；左侧对象树同样能看到字段说明。
- **语法错误也能指到具体位置**：SQLite 原生报错对零基础等于没说（`near "AS": syntax error`）。现在先用他自己写的那句话做体检，直接说清哪一段有问题、该怎么改——中文标点会标出位置并提醒「按一下 Shift 切换中英文输入法」；列与列之间忘了逗号会把他原文切成几段展示；表名和字段名粘在一起（`products_name`）会说明「表名放 FROM 后面、字段名放 SELECT 后面」。写的时候实时提示，不等执行。
- **先教规则再让他写**：每关任务卡上有「这一关的语法要点」，从参考 SQL 自动推出——列之间用英文逗号、别名用 `AS`、文字值加英文单引号、判空用 `IS NULL` 等，最多三条。
- **编辑器永远是空的（第 1 关到第 19 关）**：不预填示例、不给可以照着改的模板。空白下面会写明「这是故意的」，并把你引导到「怎么想出来」。
- **怎么想出来（不是给格式照着填）**：右侧按「问题 → 这一步在做什么 → 为什么必须有它 → 新手常错在哪」逐段拆解。比如 WHERE 那段问的是「有没有不需要的行要先剔除？」，并解释「表里混着已取消的订单，不筛算出来的数就偏大——这就是口径」。**不给可插入的骨架**，想不出来就按提示阶梯走：方向提示 → 结构提示 → 参考写法。
- **值一点就插入**：从每关的参考 SQL 自动抽出会用到字面值（`'paid'`、`'2026-06-16'`、`'%蓝牙%'`、`NULL`…），列成一排可点击的按钮，**连英文单引号一起给你**——小白不需要自己打引号，也就不会因为中文引号写错而跑不出来。
- **一边写一边体检**：不等执行就给反馈。中文标点、中文引号（“ ” ‘ ’）、单引号没配对、还没写 SELECT、这一关还缺哪个子句，实时显示在编辑器下方。
- **辅助会随水平退场**：关键字快捷词只留 `SELECT / FROM / WHERE / AND / OR` 五个，而且**只在第 1–6 关出现**，从第 7 关起自动消失——那时候你已经能自己写了。真正一直保留的只有两样「防错」辅助：点字段名插入、点常用值插入（连英文单引号一起给）。

## 错题会回来找你：周会复盘

做错的关卡会进入「待改进」盒子，**1 天 / 3 天 / 7 天**后各复现一次，每次都用**同一知识点、不同业务场景**的变体题——不是重做原题，防止背答案。

| 时机 | 发生什么 |
|---|---|
| 某关答错 | 进入待改进，1 天后到期；顶栏「周会复盘」出现红点 |
| 到期 | 关卡地图顶部出现横幅：「今天有 N 道复盘题」，一次最多做 3 道 |
| 复盘做对 | 往前走一档（1 天 → 3 天 → 7 天），每题 +15 奖金 |
| 三档都过 | 移出待改进，记入「已掌握」 |
| 没到期 | 也可以「提前复盘」，只是顶栏不提醒 |

变体题一共 19 道（每关一道），全部由 `npm run verify:variant` 验证能跑出结果、且与原题结果不同。复盘页里沿用的是**原关卡的三段提示**——知识点相同，只是场景变了。

## 零基础第一课（14 节短课）

首页最显眼的位置是「基础课 · 14 节短课」，专门服务完全没接触过 SQL 的人。每节课都走同一套流程：

**是什么 → 有什么作用 → 最小示例 → 玩家动手写 → 即时反馈 → 一句话总结**

14 节依次覆盖：数据库与表（行/列/列名/字段）→ 逗号·空格·分号 → AS 别名与表头 → WHERE 与字符串单引号 → 运算符 → AND/OR → ORDER BY → LIMIT → DISTINCT → 聚合函数与括号（COUNT/SUM）→ GROUP BY → HAVING → JOIN 基础 → NULL 与 IS NULL。

每节课的参考答案都由 `npm run verify:lesson`（43 项）验证能跑出结果；文案长度也有约束（是什么/有什么用 ≤ 60 字、提示的「怎么做」≤ 34 字），避免堆字。

## 术语随时可查

白话文案里出现专业名词（数据库、表、行、列、列名、字段、表头、别名、关键字、字符串、NULL、运算符、函数、聚合函数、表名）时会带**虚线下划线**，鼠标停住就显示「是什么 + 最小示例」。数据字典页底部还有一张完整的**名词解释**表（15 条，每条配示例）。

## 首屏不用等数据库

SQLite 引擎（643KB）和练习数据（777KB）合计约 1.4MB，原来要等它加载完才能看到第一屏。现在改成**按需加载**：

- 首页和关卡地图不需要数据库 → **立刻渲染**（实测把数据文件人为延迟 8 秒，首屏仍然 0.23 秒出现）；
- 你在首页停留时，它在后台预热，等你点进关卡通常已经准备好了；
- 万一还没好，顶部会出现「正在准备数据库」的提示条，执行按钮暂时禁用——不会让你以为点坏了。

## 我的数据

顶栏「我的数据」把学习成果集中在一页：当前职级与月薪、**6 级职级阶梯**（标出已达成/当前/还差几关）、**能力分布**（基础查询 / 聚合统计 / 多表关联 / 业务分析，各自显示完成度、进度条和平均星级）、**待改进项**（做错的知识点 + 是第几次复习 + 什么时候到期，可直接去复盘）、**基础课 14 节进度**，以及一键「复制成绩单」。
- **其他写法（做完之后看）**：同一件事的另一种写法，每条都附「为什么这么写」。**34 条全部通过了对应关卡的自动判定**（`npm run verify:alt`），确保不会教错。通过本关后才解锁——先自己写出来，再看别人的写法才有意义。
- **右栏不堆料**：所有教学内容折成 6 个分区，默认只展开「任务要求」和（前几关的）「怎么想出来」，其余（表和值 / 这关在教什么 / 提示 / 其他写法）收成一行标题，点开才展开。
- **提示一眼能点**：三条提示不再藏在一个按钮后面，而是三行并列写明「点开看：方向提示 / 结构提示 / 参考写法」，行尾标着「点这里」，点哪条开哪条。
- **三段式提示**：方向 → 结构 → 参考写法。用提示只影响星级，不影响能否通关。
- **永不锁关、永不扣薪**：月薪只涨不跌，卡关只是「待改进项」。
- **职级与薪资**：6 级（实习生 ¥3000 → 数据负责人 ¥25000），完成 4 关升一级，升职时弹一张可复制的工资条。
- **中文报错翻译**：`no such column: amout` → 「没有找到字段，你是不是想写 `amount`？」；字段名有歧义、括号没闭合、聚合函数用在 WHERE 里，都有对应的解释。

## 数据

一家虚构电商公司 2026 年 3–8 月的经营数据：9 张表、600 用户、50 商品、2500 订单、约 6000 条明细，另有支付、退款、物流、埋点、优惠券。

关卡共 19 关：基础线 1–13（`SELECT` → 选列与别名 → `WHERE` → 多条件 → `LIKE` → `IS NULL` → `ORDER BY` + `LIMIT` → `DISTINCT` → 聚合 → `GROUP BY` → `HAVING` → `JOIN` → `JOIN` + 分组），业务线 14–19（渠道看板 → 爆款 → 复购 → 新老客 → 月度趋势 → Boss 退款率排查）。第 13 关是专门补的过渡关：把 JOIN 和分组合起来做一次简单统计，避免从「两表关联」直接跳到四列综合报表。

故意埋进去的「脏数据」（这是教学核心，不是 bug）：

| 陷阱 | 位置 | 对应的学习点 |
|---|---|---|
| 已取消、已退款的订单也在表里 | `orders.status` | 算 GMV 忘记过滤就会偏大 |
| 早期用户的获客渠道为空 | `users.channel` | 分组统计漏掉 NULL、`COUNT(*)` 与 `COUNT(列)` 的区别 |
| 未送达的订单到货时间为空 | `shipments.arrive_time` | 内连接丢行，`LEFT JOIN` 的意义 |
| 优惠金额 0 与 NULL 混用 | `order_items.discount_amount` | `COALESCE` / `IS NULL` |
| 少量用户手机号重复 | `users.phone` | 一人多账号，`DISTINCT` 的必要性 |
